# 需求说明：按规则保存抓包响应，并按路径回放

插件名 `whistle.replay`。用户要两件事：按指定规则把抓包响应落成文件；之后按路径自动回放这些结果。下面是已经拍板的行为。保存规则用来决定「哪些响应要落盘」，回放不再依赖手写 Mock 规则或勾选文件。

## 用户目标

1. 能保存「指定规则」匹配到的请求，把抓包响应落成以后可以回放的文件。
2. 之后能按 URL 自动匹配这些保存结果并回放。

## 已定行为

1. **回放查找文件时只比较路径（pathname）。** 不比较协议、主机、端口、query、hash，也不用子串或正则。路径按 URL 解析结果原样比较，不合并末尾斜杠，不忽略大小写。是否允许回放还可以按白名单里的域名过滤，见第 3 条；域名不进入匹配键。
2. **同一匹配键有多份保存时，回放最早的那一份。** 匹配键跨保存目录一起比，时间更早的优先；时间相同则按保存规则的先后顺序。
3. **回放有总开关，默认开启。** 关闭时一律不回放，请求继续访问真实服务器。开启时，只有命中「需要回放」白名单的请求才回放。每条白名单可以填写域名、路径，或两者都填，并可再用 HTTP 方法过滤；方法留空表示全部方法。域名只比较主机名，不含协议和端口，比较的是 URL 解析出的主机名（小写）。路径只比较 pathname。两者语法相同：子串，或 `/正则/`、`/正则/i`。只填域名时该主机下任意路径都可回放；只填路径时任意域名；两者都填必须同时命中。多条白名单是「命中任意一条才回放」。未命中继续访问真实服务器。白名单只在回放开关开启时生效。找到文件仍按 pathname + 方法，和白名单是否填写域名无关。不再另设不回放名单，也不再手写 Mock 规则或勾选文件。
4. **匹配键是 pathname + HTTP 方法。** 方法忽略大小写。不使用请求体。
5. **回放还原原始状态码、响应头和响应体。** 同时把保存时的请求侧信息记下来：请求头、请求体，以及当时的 URL、pathname、方法。这些请求侧信息用于匹配（只用 pathname 和方法）和事后查看，不会把请求再发一遍。
6. **对不上保存结果时，继续访问真实服务器，不返回错误。** 最早那份文件已经不在磁盘上时，同样视为对不上。
7. **空响应、二进制（如图片）、超过大小上限的响应不保存。** 响应类型仍只收 JSON、普通文本和 SSE。
8. **展示索引用 `.replay-index.json`，最多留较新的 500 条。** 回放不依赖这 500 条。每个保存目录另有 `.replay-replay.json`，按匹配键只留最早一份，不按 500 条裁剪。因此更旧的文件只要仍是该键的最早一份，就能回放。这两个文件在用户指定的保存目录里，文件名用 replay 前缀，避免和现网 `whistle.sake` 写到同一位置。插件配置存在 whistle 按插件名分开的存储里，不使用这些文件名。
9. **回放产生的响应不再保存。**

## 保存

`rules.txt` 为 `* whistle.replay://none`，经过 whistle 的请求都会进入保存钩子和动态规则钩子。保存有总开关。开关打开后，请求要同时满足下面几项才落盘：

- 完整 URL 命中某条已启用保存规则。这里的匹配仍是子串，或 `/正则/`、`/正则/i`，作用在 whistle 提供的 URL 上（优先 `fullUrl`），不是回放用的 pathname 精确比较。
- HTTP 方法命中。方法列表为空表示不限方法。
- 响应 `Content-Type` 能分成 JSON、普通文本或 SSE。
- 可选的状态码过滤通过。留空表示不限。
- 响应体非空，且不是 whistle 未给出文本的二进制正文。
- 未超过该规则的大小上限（KB）。`0` 表示不限响应体大小，界面上限为 10240 KB。
- 不是本次回放产生的响应，也不是插件内部的 SSE 回放请求。

命中后写入该规则自己的绝对路径目录：

- 响应体：JSON 为 `.json`，文本和 SSE 为 `.txt`。文件名仍是 `{whistle 用户名前缀}{路径末段}_{时间戳}`。
- 若规则打开了 JSON 格式化，落盘和之后回放的正文是格式化后的内容。
- 同一条响应可以命中多条保存规则，每条规则各写一份。
- 同目录的 `.replay-replay.json` 记下回放所需的整份记录。展示索引 `.replay-index.json` 仍最多 500 条，供界面查看较新的文件。

每份回放记录包含：pathname、方法、完整 URL、保存时间、状态码、响应头、响应体文件名、请求头、请求体。

请求体按 UTF-8 文本保存。超过该规则的大小上限时不写请求体，响应仍然保存。规则没有设上限时，请求体最大按 10240 KB 写入，再大就不写请求体。whistle 没有给出文本请求体时也不写。这两种情况把 `requestBodyOmitted` 标为 true。

回放用的响应头会去掉传输层字段：`connection`、`keep-alive`、`proxy-connection`、`transfer-encoding`、`te`、`trailer`、`upgrade`、`content-length`、`content-encoding`。其余响应头按抓包结果回放。单个头值超过 8192 字符，或超过 100 个头时截断。

白名单只决定是否回放，不决定是否保存。未命中白名单的请求若命中保存规则，仍会把真实响应落盘。

配置界面可以维护保存规则和「需要回放」白名单，两者各有总开关，层级相同。回放开关默认开启。规则改完要点「更新配置」才写入。规则条数上限 200。保存目录必须已存在。界面可以查看某个保存目录里的文件，并看到状态码、响应头和请求侧信息。

## 回放

请求到来时：

1. 内部 SSE 回放请求直接放过，避免循环。
2. 回放总开关关闭时，访问真实服务器。
3. pathname 或方法无法得到时，访问真实服务器。
4. 未命中任一启用的白名单时，访问真实服务器。只填域名则该主机任意路径可回放；只填路径则任意域名；两者都填必须同时命中。方法限制仍然生效。
5. 在全部保存规则的目录里查找该 pathname + 方法的最早记录。目录来自保存规则里填写的路径，规则暂时停用也仍然参与查找。
6. 找不到，或对应文件已不在，则访问真实服务器。
7. 找到则直接返回该文件的响应体，并带上保存时的状态码和响应头（含 200）。SSE（`Content-Type` 含 `text/event-stream`）按事件逐段推送；内部推送服务不可用，或响应头过长时，改为一次性返回正文。

回放不会使用固定 / 轮换 / 随机，也不会另配状态码、响应头、延迟或命中率。
